# Governance and sustainability proposal

Status: Founding intentions and an interim proposal. No independent foundation, elected council, institutional partnership, grant award, or external governing body has been established through this repository.

## Purpose

Steward AiRC Nexus as shared infrastructure for reliable knowledge exchange among humans and AI. The protocol and core platform are intended to be open source. Participants should be able to operate their own nodes and retain authority over their information.

Long-term governance should support the public benefit, scientific integrity, privacy, transparent decisions, and participation beyond any single organization.

## Initial stewardship

The project begins in the public `AiRC-ai/AiRC-Nexus` repository. Repository hosting and the founding vision establish a starting point; they do not imply an existing community governance structure.

During the concept stage, the founding maintainer coordinates documentation and records decisions in the repository. Identify maintainers, reviewers, decision authority, and escalation contacts publicly as people accept those roles. Agents can propose changes and provide evidence; accountable people authorize project decisions.

## Proposed decision process

1. Open a proposal describing the problem, affected participants, alternatives, evidence, and consequences.
2. Invite review from the relevant technical, security, research, or community participants.
3. Record the decision, its owner, rationale, unresolved objections, and a review trigger.
4. Implement through a reviewed change. Keep revisions and later reversals visible.

Use pull requests for substantive documentation and future implementation changes. Separate accepted decisions from proposals. Security-sensitive details need a confidential path; publish a suitably redacted outcome once disclosure is appropriate. Repository branch protections and formal voting rules remain to be selected.

## Community structure to explore

- A technical group responsible for protocol compatibility, implementations, and release quality.
- Security and privacy reviewers responsible for abuse handling, incident processes, and control requirements.
- Researchers and domain experts responsible for evidence profiles and scientific review expectations.
- Contributors, users, and node operators represented in policy, usability, and sustainability decisions.

A nonprofit foundation or neutral fiscal host is an option for later evaluation. Entity formation, membership, voting, conflicts of interest, succession, and trademark stewardship require explicit decisions; none is settled by this document.

## Knowledge stewardship

- Contributors retain control of private material and identify what they are authorized to share.
- Public records preserve attribution, evidence, corrections, negative findings, and permitted uses.
- Reviewers disclose relevant affiliations and conflicts. Financial support or agent reputation must not substitute for evidence.
- Moderation requires documented reasons, proportional action, an appeal path, and emergency procedures.
- Distinguish the platform's software governance from editorial decisions about individual knowledge records.
- Define which policies are required for interoperability and which remain under each node operator's control.

## Licensing decisions

No license has been selected. Before accepting implementation contributions, agree on and document:

| Asset or activity | Decision needed |
| --- | --- |
| Protocol and core software | Open-source license, compatibility goals, and third-party obligations |
| Documentation and specifications | Documentation license and attribution terms |
| Knowledge records and evidence | Per-record source rights, contribution terms, permitted reuse, and artifact-specific restrictions |
| Contributions | Contributor attestation and whether a DCO or other agreement is appropriate |
| Name and identity | Trademark ownership and community use policy |

A software license does not decide how third-party datasets, papers, or restricted evidence may be distributed. Resolve those permissions for each relevant source and artifact. The initial repository intentionally has no `LICENSE` file while this decision is open.

## Sustainable operation

Investigate research grants, philanthropic support, university partnerships, corporate sponsorships, donated infrastructure, and optional hosting/support services compatible with the public mission. No revenue model, sponsor benefit, grant eligibility, or funding commitment is approved here.

Publish an operating model covering hosting, indexing, storage, validation compute, independent review, moderation, security response, and maintenance. Measure cost per useful reuse and review capacity before expanding intake. Avoid relying on an unlimited supply of donated compute or permanent unpaid moderation.

The [research notes](research.md) identify funding leads for investigation. Any application requires a separate eligibility review, accountable applicant, realistic budget, and current solicitation checks.

## Decisions needed before a public service

- Named operators, maintainers, moderation owners, and confidential security contacts.
- Software, documentation, and knowledge contribution licensing.
- Participation rules, a code of conduct, conflict disclosure, and appeal processes.
- Privacy, retention, access revocation, correction, and withdrawal policies.
- Domain-specific evidence and review policies.
- Federation admission/removal rules and incident coordination.
- A funded operating budget with clear service and support expectations.
