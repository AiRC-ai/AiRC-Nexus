# Separate-host HTTPS acceptance — November 16, 2026

The v0.3 reference runs on two distinct Ubuntu hosts using separate local PostgreSQL containers and unique logical operator/agent accounts. Each has its own endpoint-generated TLS key/leaf and Ed25519 signing identity. Both HTTPS previews rendered in the native in-app browser with normal trust and no certificate bypass. One project administrator still controls the environment; this is not independent institutional governance or physical-fault-domain proof.

## Verification

- **47/47 unit/integration tests passed.** New cases cover trusted TLS and hostname validation, wrong root/name rejection, redirect refusal, absolute deadlines/byte limits, unique minimal operator provisioning, secure host-only cookies and spoofed forwarding/origin rejection.
- **Six existing browser journeys passed** after the transport changes, covering the earlier local workflows and two-hostname session isolation.
- The live HTTPS scenario completed **16 bounded screening/propagation phases** across the separate hosts. Both directions passed opt-in, recipient review and exact origin/revision retrieval through official MCP stdio clients.
- Source sharing opt-out, immediate recipient opt-out, private correction, new source/recipient approvals and withdrawal all passed. The old revision stayed unavailable; the withdrawal test record remains withdrawn.
- Three authored private/team fixtures stayed on their originating hosts. Database hash checks found **zero foreign private titles** in either native revisions or the peer cache. The requester-private outcome existed only in its own node's outcome table and was absent from anonymous/source views.
- Each deployed database had exactly one human, one agent and one anonymous principal. Operator IDs and agent credentials were unique; cross-node credential use and cross-origin mutations were rejected.
- The deployed APIs held only their application database secret; no administrative, worker or verifier URL was loaded. The application/verifier/proxy roots remained read-only with capabilities dropped.

## TLS and operational evidence

Both full chains verified to the trusted private root and matched the configured DNS identities. A client using the wrong root was rejected; IP/wrong-hostname use was rejected by the same Node HTTPS stack used by the application. A forced North leaf renewal succeeded, changed the certificate serial, and the proxy served the new leaf while retaining normal chain/hostname validation. The renewal sidecar holds no CA administrative credential.

Before issuance, a fresh stopped-state CA backup was encrypted, test-decrypted and mirrored with matching hash. Only public CSRs left the endpoints; the offline root stayed unmounted. The host FQDNs were already allowed, so no CA policy or DNS expansion was required. The standard PKI monitor passed again with zero critical findings, warnings or gaps; the two new listeners were validated separately.

The second host had no automatic Docker address pools left. Explicit, checked private subnets were assigned only to the Nexus stacks. No unrelated network was pruned and no global daemon or firewall rule was changed. PostgreSQL's mount root was assigned to its unprivileged user; the proxy's scratch directories stayed on tmpfs rather than making its root writable.

The application image `sha256:e903ae4e85b81049f99a1b087df2f6d341598e29a8fcdf8e0a3cb8ba0beab1fb` was built from source checkpoint `0e1f6c2` and transferred unchanged to the second host. Deployed API, transport and federation-service byte hashes matched the current compiled source on both hosts. Deployment-only fixes are retained in the final source alongside the acceptance harness. Private inventory, codes, tokens, keys, database files and raw evidence are excluded from Git.

## Remaining boundary

This is an authenticated managed LAN/VPN pilot with private-CA trust and authored examples. It is not a public Internet release, independent scientific replication, full security audit, outside-operator enrollment or a substitute for expert research review. MFA/SSO, unattended agent-credential rotation, independent key custody, wider clock/restore failure testing, retention/privacy operations and the held-out smaller-model comparison remain future work. The original knowledge-commons principles and per-node data control remain unchanged.
